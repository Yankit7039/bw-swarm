# SWARM

**SWARM** is an agent orchestration platform built for telecom and network operations. Teams describe automations in **workflow YAML**, trigger them over **HTTP** or **webhooks**, and watch every step in a single **Admin Console**, without standing up a new integration stack for every use case.

Whether you are evaluating SWARM for your organization, rolling it out in production, or authoring the next automation, the same documentation applies: **what each part does**, **why it exists**, and **how it fits together**.

---

## What SWARM solves

Enterprises run complex, ticket-driven work: stuck orders, number porting, eSIM, network triage, and customer comms across many systems. SWARM gives you:

- **One place to run:** A consistent path from trigger to completion, with status and history you can trust.
- **Declarative workflows:** Automations are defined as YAML, versioned and reviewed like any other critical config.
- **Shared integrations:** External systems are reached through a **tool gateway** so workflows stay portable and readable.
- **Visibility:** Operators see runs, events, and tooling in the console; APIs expose the same picture for dashboards and audits.

SWARM is opinionated about **clarity** and **repeatability**: the platform handles orchestration and handoffs so your teams focus on the business logic in the workflow.
