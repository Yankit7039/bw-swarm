# Built-in templates

Each **template** is a **Docker image** plus a **`template_id`** registered in Postgres. Most images **extend `swarm-core`** and copy **`workflow.yaml`** to **`/app/workflow.yaml`**.

<Callout type="tip" title="Number porting is different">
  The **number-porting** template is a **standalone** Python package (not `FROM swarm-core`) — see **Number porting resolution** below. Operational pattern (warm pool, **`POST /run`**) still matches the platform.
</Callout>

## Stuck order resolution

**Purpose:** Diagnose and progress **stuck telecom orders** across order management, CRM, Ericsson, and Netcracker; escalate and notify.

**Stages:** Four **`hybrid`** stages — **enrich** → **investigate** → **resolve** → **notify** — each with **`llm_agent`** steps and **`tool_filter`** lists (OMS, Siebel, Ericsson, Netcracker, escalation, notification).

**Image:** `FROM swarm-core` (or build arg **`BASE_IMAGE`**); YAML may be omitted from the image if the row in **`templates.workflow_yaml`** is populated.

## Ticket email routing

**Purpose:** Classify **Jira** issues, look up escalation matrix, send **AgentMail** messages, and run **[AgentMail follow-up](/followup-lifecycle)** (initial → follow-up → engineer reply).

**Stages:** Mix of **`deterministic`** and **`hybrid`** with **`skip_if`** on **`is_followup`** / **`is_reply`**.

**YAML:** **`follow_up.mode: agentmail`**.

## Network ops L1/L2 triage

**Purpose:** **Network operations** triage — ingest ticket, enrich from OSS/NetCracker/ServiceNow KB, classify, update **Jira** (comments, labels, priority).

**Routing:** Jira webhook **issue key** starting with **`NET`** selects this template (see [Runtime](/service-runtime)).

## eSIM activation resolution

**Purpose:** eSIM activation issues with **`poll_loop`** stages: **poll** provisioning/fraud, **escalate** on a ladder.

**Stages:** **`hybrid`** classify/route + **`poll_loop`** with **`poll_steps`** and **`escalation_ladder`**.

## Number porting resolution

**Purpose:** **Porting** workflows — validation, fraud checks, **porting gateway** retries, **runbook** escalation.

**Image exception:** **`Dockerfile`** uses **`python:3.12-slim`**, installs **`number_porting_resolution`** from **`pyproject.toml`**, and runs **`uvicorn entrypoint:app`** — **not** the swarm-core base image. Operational pattern (warm pool, **`POST /run`**) still matches the platform.

## Template image pattern (swarm-core)

```dockerfile
ARG BASE_IMAGE=swarm-core:latest
FROM ${BASE_IMAGE}
COPY stuck-order-adk.yaml /app/workflow.yaml
# Optional: ENV YAML_PATH=/app/workflow.yaml (default)
```

Build **swarm-core** first, then:

```bash
docker build -t stuck-order-adk:latest ./templates/stuck-order-adk
```
