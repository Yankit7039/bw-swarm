# How workflows work

A **workflow** is the executable definition inside a **template pod**: validated **YAML** consumed by **swarm-core**, which drives **Google ADK** (agents + tools) and persists state to **Postgres**.

## Run lifecycle

<Callout type="info" title="YAML resolution">
  The pod loads workflow text from **`YAML_PATH`** on disk when present; otherwise it reads **`templates.workflow_yaml`** via **`fetch_workflow_yaml(run_id)`** for that run’s template.
</Callout>

1. **Trigger** — Something asks the runtime to start work: **`POST /runs`**, a **Jira** webhook, or internal scheduling (e.g. follow-up poller).
2. **Record** — Runtime inserts **`runs`** with status **`pending`** and the **payload** (e.g. `order_id`).
3. **Allocate** — **SandboxClaim** binds a **warm** (or cold) pod for the template’s image.
4. **Dispatch** — Runtime **`POST`s** to the pod **`/run`** with **`run_id`** (UUID) and **`payload`**.
5. **Load YAML** — The pod resolves workflow text:
   - If **`YAML_PATH`** (default **`/app/workflow.yaml`**) exists → load from disk.
   - Else → **`fetch_workflow_yaml(run_id)`** reads **`templates.workflow_yaml`** via the **`runs`** → **`templates`** join.
6. **Validate** — **`WorkflowSchema`** (Pydantic) ensures stages and steps match allowed types.
7. **Branch** — If **`follow_up.mode == agentmail`**, **`followup_agentmail.run_agentmail_workflow`** handles multi-phase email logic; otherwise **`_run_standard_workflow`** runs the generic ADK loop.
8. **Complete** — Status becomes **`completed`** or **`failed`**; **`run_events`** holds the timeline (tools, stages, LLM snippets, follow-up events).

## Inputs and outputs

- **`input.required`** in YAML lists **payload keys** the runner expects (e.g. `order_id`, `ticket_id`).
- **`result_keys`** names keys copied from session state into the **`runs.result`** JSON on success (standard path).
- **`tool_labels`** maps MCP tool names to human-readable labels in **`run_events`**.

## Standard vs AgentMail paths

<Tabs items={["Standard", "AgentMail"]}>
  <div>
    **Use case:** One-shot or poll-loop workflows.

    **Entry:** `workflow_runner._run_standard_workflow`

    **Persistence:** Result + **`run_events`**.

    **Runtime workers:** N/A (no follow-up poller for this path).

    **Key fields:** **`result_keys`**, session state copied into **`runs.result`** on success.
  </div>
  <div>
    **Use case:** Escalation email + scheduled follow-ups + engineer replies (`follow_up.mode: agentmail`).

    **Entry:** `followup_agentmail.run_agentmail_workflow`

    **Persistence:** Result + events **plus** **`state`**, **`followup_due_at`**, **`communication_threads`**, **`pending_inbound_interactions`**.

    **Runtime workers:** **`followup_poller`**, **`pending_reply_worker`**.

    See [Follow-up lifecycle](/followup-lifecycle) for the AgentMail state machine.
  </div>
</Tabs>
