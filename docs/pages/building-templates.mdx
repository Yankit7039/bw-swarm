# Building a new template

<Steps>
  <div>
    **Author workflow YAML**

    - Start from [Workflow YAML reference](/yaml-reference) and [Stages and steps](/stages-and-steps).
    - Pick **stage types** (`hybrid` vs `poll_loop`) and **steps** (`mcp_call`, `llm_agent`, `condition`).
    - Declare **tool names** that exist in the [Adapter reference](/adapters) (`adapter__tool`).
  </div>
  <div>
    **Validate locally**

    - Copy YAML to **`/app/workflow.yaml`** in an image, **or** set **`YAML_PATH`** to a mounted file.
    - Pod startup calls **`load_and_validate_workflow_yaml`** when the file exists — bad YAML fails fast.
    - Run **`swarm-core`** tests or a one-off container with **`DATABASE_URL`** and **`OPENROUTER_API_KEY`**.
  </div>
  <div>
    **Dockerfile**

    **Standard path:**

    ```dockerfile
    ARG BASE_IMAGE=swarm-core:latest
    FROM ${BASE_IMAGE}
    COPY my-workflow.yaml /app/workflow.yaml
    ```

    Build **swarm-core** first (`docker build -t swarm-core:latest ./swarm-core`).
  </div>
  <div>
    **Register the template in Postgres**

    Insert a row into **`templates`**:

    - **`template_id`** — matches YAML **`template_id`**
    - **`name`** — display name
    - **`image`** — image reference (local tag or ECR URL)
    - **`warm_pool_ref`** — name used by **SandboxWarmPool** in Kubernetes (see [Infrastructure](/infrastructure))
    - **`workflow_yaml`** — optional; if set, pods can omit the file on disk and load from DB per run
  </div>
  <div>
    **Push image and deploy warm pool**

    - Push to **ECR** (see [AWS deployment](/aws-deployment)).
    - Apply the matching **`warmpool-*.yaml`** in **`infra/k8s-aws`** (or Kind) so idle pods use your image.
  </div>
  <div>
    **Trigger a run**

    ```bash
    curl -X POST http://<runtime>/runs \
      -H "Content-Type: application/json" \
      -d '{"template_id": "<your-template-id>", "payload": { ... }}'
    ```
  </div>
  <div>
    **Operate without baking YAML**

    For rapid iteration, **PATCH** **`workflow_yaml`** via **Admin API** (`PATCH /templates/{template_id}`) so pods in **DB mode** fetch fresh YAML on each run (no image rebuild). Production still typically pins YAML in images for reproducibility.

    <Callout type="tip" title="Iterate without rebuilding images">
      **DB mode** + Admin API **`PATCH`** lets you change workflow YAML on every run — ideal for dev; pin YAML in images for reproducible production builds.
    </Callout>
  </div>
</Steps>
