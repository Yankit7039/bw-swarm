# Deploying to AWS (EKS)

Production SWARM runs on **Amazon EKS** with **RDS Postgres**, **ECR** images, **Secrets Manager** (via **External Secrets**), and **Application Load Balancers** for ingress. This page summarizes the path; detailed commands and account-specific values also live in **`AWS_QUICKSTART.md`** and **`docs-old/AWS_DEPLOYMENT.md`** at the repo root.

## Prerequisites

- **AWS CLI v2** configured for the target account and region (default in repo docs: **`ap-southeast-1`**)
- **Terraform** ≥ 1.6
- **Docker**, **kubectl**, **curl**
- Permissions for VPC, EKS, RDS, ECR, IAM, Secrets Manager, ELB, etc.

<Steps>
  <div>
    **Bootstrap Terraform remote state (once per account)**

    If the S3/DynamoDB backend is not yet created:

    ```bash
    terraform -chdir=infra/terraform/backend init
    terraform -chdir=infra/terraform/backend apply
    ```

    Capture **`state_bucket_name`** and **`lock_table_name`** — they must match **`infra/terraform/prod/main.tf`** backend configuration.
  </div>
  <div>
    **Configure secrets (tfvars)**

    Edit the environment’s tfvars (e.g. **`infra/terraform/prod/dev.tfvars`** or **`terraform.tfvars`**):

    | Variable | Purpose |
    |----------|---------|
    | `openrouter_api_key` | LLM calls from template pods |
    | `agentmail_api_key`, `agentmail_inbox_id` | AgentMail MCP + sync to `adk-secrets` |
    | `jira_email`, `jira_api_token`, `jira_base` | Real Jira tools for ticket templates |
    | `jira_webhook_secret` | Verifies **`POST /webhooks/jira`** on runtime |
    | `agentmail_webhook_secret` | Svix-style signing for **`POST /webhooks/agentmail`** |

    Use placeholders if a service is not wired yet; adapter may mock sends.
  </div>
  <div>
    **Deploy core infrastructure**

    ```bash
    cd infra/terraform/prod
    terraform init
    terraform workspace select default   # or dev workspace per your Makefile
    terraform apply
    ```

    Terraform typically provisions:

    - **VPC** (public + private subnets)
    - **EKS** cluster + managed node groups
    - **RDS** Postgres
    - **ECR** repositories (**swarm-core**, template images, **swarm-adapter**, **swarm-runtime**, **swarm-admin-api**)
    - **Secrets Manager** secret (e.g. **`swarm-prod/adk-secrets`**) and **External Secrets Operator**
    - **AWS Load Balancer Controller** (Helm)

    **Useful outputs:**

    ```bash
    terraform -chdir=infra/terraform/prod output
    terraform -chdir=infra/terraform/prod output -json ecr_repository_urls
    ```
  </div>
  <div>
    **Build and push images**

    The **Makefile** at the repo root defines the image matrix and ECR login:

    ```bash
    make deploy ENV=dev    # or ENV=prod
    ```

    That runs Terraform, **`aws ecr get-login-password`**, builds images (swarm-core, runtime, adapter, admin-api, all template images), pushes to ECR, applies **`infra/k8s-aws`** manifests in order, and health-checks.

    Images include:

    - `swarm-core`
    - `swarm-runtime`, `swarm-adapter`, `swarm-admin-api`
    - `stuck-order-adk`, `esim-activation-adk`, `number-porting-adk`, `ticket-email-routing-adk`, `network-ops-l1l2-triage-adk`

    <Callout type="info" title="Typical deploy duration">
      End-to-end **`make deploy`** is usually on the order of **20–25 minutes**; destroy **12–15 minutes** (ALB teardown can take longer).
    </Callout>
  </div>
  <div>
    **kubectl apply order (manual)**

    <Callout type="danger" title="Apply manifests in order">
      Do **not** `kubectl apply -f infra/k8s-aws/` in one shot — **CRDs must exist first**. Follow **`infra/k8s-aws/README.md`** and apply in this sequence.
    </Callout>

    1. **`agent-sandbox-manifest.yaml`** — core controller + CRDs
    2. **`agent-sandbox-extensions.yaml`** — SandboxTemplate / WarmPool CRDs
    3. Wait for CRDs to be **established**
    4. **External secrets**, RBAC, **adapter**, **runtime**, **admin-api**
    5. **Warm pool** manifests (one per template)
    6. **Ingress** (runtime + admin)

    Replace **`<AWS_ACCOUNT_ID>`** (and image tags) in deployment YAMLs to match your ECR URLs.
  </div>
  <div>
    **Verification**

    ```bash
    kubectl get pods -n default
    kubectl get ingress
    curl "$(terraform -chdir=infra/terraform/prod output -raw runtime_url)/health"
    ```

    See **`AWS_QUICKSTART.md`** for a troubleshooting table (`kubectl logs`, `kubectl describe`, etc.).
  </div>
</Steps>
