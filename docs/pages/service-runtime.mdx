# Runtime service

**Code:** `runtime/` — FastAPI app in **`runtime/app.py`**.

**Role:** Owns **run creation**, **Kubernetes SandboxClaims**, **HTTP dispatch** to template pods, **Jira** and **AgentMail** webhooks, and background tasks: **`claim_reconciler`**, **`followup_poller`**, **`pending_reply_worker`**. **Postgres only** (no Redis in code paths).

## API

| Method | Path | Description |
|--------|------|-------------|
| **POST** | `/runs` | Body: `{ "template_id": string, "payload": object }`. Creates run, returns **`run_id`**, **`status`: `pending`**; schedules **`trigger_run`**. |
| **GET** | `/runs/{run_id}` | Run row: status, result, errors, timestamps, etc. |
| **GET** | `/runs/{run_id}/events` | Ordered **`run_events`**. |
| **GET** | `/health` | `{ "status": "ok" }`. |

## Webhooks

<Callout type="warning" title="Webhook authentication">
  **Jira:** **`X-Hub-Signature: sha256=<hex>`** (HMAC of raw body, **`JIRA_WEBHOOK_SECRET`**) **or** **`Authorization: Bearer <same secret>`** for manual tests.

  **AgentMail:** Svix-style headers **`svix-id`**, **`svix-timestamp`**, **`svix-signature`**; secret **`AGENTMAIL_WEBHOOK_SECRET`** must start with **`whsec_`** for HMAC key derivation.
</Callout>

### Jira — `POST /webhooks/jira`

- Query **`order_id`** = Jira issue key.
- Body must include **`webhookEvent`: `jira:issue_created`** for the async task to proceed.

**Routing:**

- Issue key **starts with `NET`** (case-insensitive) → template **`network-ops-l1l2-triage`**, payload **`{ "ticket_id": "<key>" }`**.
- Otherwise → **`ticket-email-routing`**, payload **`{ "order_id": "<key>" }`**.

Emits **`jira_webhook`** run event when triggered.

### AgentMail — `POST /webhooks/agentmail`

- Processes **`event_type`: `message.received`** in background.
- Resolves **`thread_id`** → **`communication_threads`** → **`run_id`**; may **queue** inbound in **`pending_inbound_interactions`** if busy, or **`trigger_sandbox_post_run`** with merged reply payload.

## Startup

- **`init_db`**, **`run_migrations`**, then async tasks: **`claim_reconciler`**, **`followup_poller`**, **`pending_reply_worker`**.

  These are representative — see deployment manifests for the full set wired from secrets.
</Callout>

| Variable | Purpose |
|----------|---------|
| **`DATABASE_URL`** | Async SQLAlchemy URL (`postgresql+asyncpg://...`). |
| **`JIRA_WEBHOOK_SECRET`** | Jira admin webhook shared secret. |
| **`AGENTMAIL_WEBHOOK_SECRET`** | AgentMail signing secret (`whsec_...`). |

Kubernetes client config uses in-cluster or kubeconfig for **SandboxClaim** creation (see **`runtime/sandbox_trigger.py`**).
